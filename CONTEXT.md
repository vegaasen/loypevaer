# CONTEXT.md — Løypevær domain glossary

This file defines the canonical terms used in Løypevær. AI agents and contributors should use these terms consistently in code, comments, commit messages, and documentation.

> **Repository note:** The directory is named `rittvær`; the app brand name is **Løypevær**.

---

## Arrangement

An **arrangement** is a single endurance event in the Løypevær data model — a race, ride, or competition that athletes can look up weather for. Arrangements are the primary domain object.

- Stored in `src/data/arrangements.json` (manual) and auto-generated JSON files (`cycling-events.json`, `triathlon-events.json`, `running-events.json`).
- Each arrangement has a stable `id` (kebab-case), a name, a discipline, an official date, and a list of waypoints.
- Accessible at `/arrangement/<id>` in the app.
- Also referred to as a **ritt** (Norwegian for "ride/race") in cycling context, but **arrangement** is the canonical data term.

**Disciplines:** `landevei`, `terreng`, `langrenn`, `triathlon`, `ultraløp`, `løping`

---

## Waypoint

A **waypoint** is a named, geocoded point of interest along an arrangement's route. Weather is fetched and displayed per waypoint.

- Stored inline in each arrangement's `waypoints` array as `{ label, lat, lon, altitude }`.
- Labels are freeform Norwegian strings (e.g. "Start – Rena", "Toppen av Sjodalsveien").
- Altitude is in metres above sea level; used for temperature corrections.
- Cycling waypoints can be enriched via `scripts/enrich-cycling-waypoints.ts` from a GPX file.

---

## Endringslogg

**Endringslogg** (Norwegian: "change log") is the human-readable history of notable changes to the Løypevær app and its data. It is surfaced at `/endringslogg` in the app.

- Auto-generated from git history: only commits prefixed with `feat:` or `fix:` (conventional commits) appear.
- Stored in `src/data/changelog.json` — do NOT manually edit; generated by `scripts/generate-changelog.ts`.
- Refreshed automatically on every push to `main` via `.github/workflows/refresh-changelog.yml`.
- Each entry has: SHA, date, type (`feat`/`fix`), optional scope, subject, and a GitHub commit link.

The term **endringslogg** is preferred over "changelog" in user-facing text to match the Norwegian-language context of the app.
